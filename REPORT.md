## Теоретическая часть

PHP является серверным языком программирования, который позволяет формировать HTML-страницы динамически, обрабатывать формы, работать с сессиями и хранить данные. Веб-приложение состоит из публичной части, закрытых разделов, бизнес-логики и слоя хранения данных.

Аутентификация нужна для проверки пользователя. После входа приложение сохраняет идентификатор пользователя в сессии и использует его при доступе к защищенным страницам. Пароли должны храниться безопасно, поэтому вместо открытого текста используется хеширование.

Валидация данных защищает приложение от некорректного ввода и снижает риск внедрения вредоносного кода. Клиентская валидация улучшает удобство, а серверная является обязательной, потому что запросы можно отправлять в обход браузера.

## Формулировка задачи

Необходимо разработать веб-приложение средней сложности на PHP. В качестве темы выбран магазин гарнитур, периферии и компьютерных комплектующих для Telegram-бота. Приложение должно содержать публичный каталог, регистрацию, вход, защищенный пользовательский раздел, админ-панель и управление данными.

## Практическая часть

Приложение построено на простой модульной архитектуре. Точка входа находится в `public/index.php`. Класс `src/App.php` выполняет маршрутизацию и вызывает нужные обработчики страниц. Работа с данными вынесена в репозитории `src/Repositories`. Общие механизмы авторизации, CSRF-защиты, валидации и хранения данных находятся в `src/Core`.

Данные хранятся в файле `data/store.json`, который создается автоматически при первом запуске. Это позволяет запустить проект без Composer, MySQL или SQLite. Для отчета добавлена SQL-схема `database/schema.sql`.

## Функциональные возможности

Публичная часть:

- главная страница с динамическими товарами, категориями и статистикой;
- каталог с формой поиска;
- карточка товара.

Пользовательская часть:

- регистрация;
- вход;
- восстановление пароля в учебном режиме;
- оформление заказа;
- просмотр своих заказов.

Административная часть:

- просмотр общей статистики;
- добавление, просмотр, редактирование и удаление товаров;
- добавление и удаление категорий;
- просмотр заказов и изменение статусов;
- создание новых администраторов.

## Сценарии взаимодействия пользователей

Гость открывает приложение и видит публичную витрину. Он может перейти в каталог, применить фильтры и открыть карточку товара. Для оформления заказа гость должен зарегистрироваться или войти.

Покупатель после входа оформляет заказ, указывая количество товара, Telegram username, телефон, адрес доставки и комментарий. После отправки заказ появляется в разделе `Мои заказы`.

Администратор входит через демо-аккаунт `admin@devicestore.local`, открывает админ-панель и управляет данными: добавляет товары, изменяет цены и остатки, создает категории, просматривает заказы и меняет их статус.

## Безопасность

В проекте применяются следующие меры:

- хеширование паролей через `password_hash()`;
- проверка паролей через `password_verify()`;
- хранение факта входа в PHP-сессии;
- проверка роли администратора перед входом в админ-панель;
- CSRF-токены во всех POST-формах;
- серверная валидация всех форм;
- экранирование вывода через `htmlspecialchars()`;
- хеширование токена восстановления пароля.

## Ответы на контрольные вопросы

1. Аутентификация - это проверка личности пользователя по логину и паролю.
2. Авторизация - это проверка прав пользователя на выполнение действия.
3. Пароли нужно хранить в виде хеша, чтобы не раскрывать исходный пароль.
4. Сессия позволяет сохранять состояние пользователя между запросами.
5. Серверная валидация обязательна, потому что клиентскую проверку можно обойти.
6. CRUD означает создание, чтение, обновление и удаление данных.
7. CSRF-токен защищает формы от подделки запросов.
