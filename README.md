# BotGear Store

Учебное PHP-веб-приложение средней сложности: магазин гарнитур, периферии и комплектующих для Telegram-бота с публичной витриной, регистрацией пользователей, заказами и админ-панелью.

Проект специально сделан без тяжелого стека: только PHP, HTML, CSS, JavaScript и локальная файловая база `data/store.json`. SQL-структура для отчета лежит в `database/schema.sql`.

## Запуск проекта

Требования:

- PHP 8.1 или выше;
- браузер;
- дополнительные пакеты и Composer не нужны.

Команды запуска:

```bash
php -S 127.0.0.1:8000 -t public
```

После запуска открыть:

```text
http://127.0.0.1:8000
```

При первом открытии приложение автоматически создаст `data/store.json` и заполнит базу начальными данными.

Демо-аккаунты:

```text
Администратор: admin@botgear.local / Admin12345!
Покупатель:     user@botgear.local / User12345!
```

Чтобы сбросить данные, остановите сервер и удалите файл `data/store.json`; при следующем запуске он создастся заново.

## Формулировка задачи

Разработать серверное веб-приложение на PHP на тему магазина для Telegram-бота. Приложение должно иметь публичную часть с динамическими данными, регистрацию и вход, защищенные разделы, роль администратора, формы с клиентской и серверной валидацией, безопасное хранение паролей и документацию.

## Функциональные возможности

- Публичная главная страница с динамическими товарами и категориями.
- Каталог товаров с формой поиска по названию, категории, типу, цене и наличию.
- Регистрация и вход пользователей.
- Хеширование паролей через `password_hash()` и проверка через `password_verify()`.
- Восстановление пароля в учебном режиме: токен хранится хешированным, ссылка показывается на странице вместо email-отправки.
- Личный раздел пользователя `Мои заказы`.
- Оформление заказа на товар после входа в аккаунт.
- Админ-панель с 5 функциями: обзор статистики, CRUD товаров, управление категориями, управление заказами, создание администраторов.
- CSRF-токены во всех изменяющих формах.
- Экранирование HTML-вывода через `htmlspecialchars()`.
- Клиентская валидация в `public/assets/app.js` и серверная валидация в `src/Core/Validator.php`.

## Сценарии взаимодействия

1. Гость открывает главную страницу и видит товары и категории, которые загружаются из базы.
2. Гость использует форму поиска в каталоге и фильтрует товары.
3. Гость регистрируется или входит в систему.
4. Авторизованный пользователь открывает карточку товара и оформляет заказ.
5. Пользователь видит созданный заказ в разделе `Мои заказы`.
6. Администратор входит в систему и открывает админ-панель.
7. Администратор добавляет, редактирует и удаляет товары.
8. Администратор добавляет категории и удаляет только пустые категории.
9. Администратор меняет статус заказа.
10. Администратор создает новую учетную запись администратора.

## Структура базы данных

В проекте используются 4 таблицы:

- `users`: пользователи, email, хеш пароля, роль `user` или `admin`, данные восстановления пароля.
- `categories`: категории товаров.
- `products`: товары магазина, цена, склад, описание, тип и изображение.
- `orders`: заказы пользователей, контактные данные, сумма и статус.

Связи:

- `products.category_id` связан с `categories.id`;
- `orders.user_id` связан с `users.id`;
- `orders.product_id` связан с `products.id`.

SQL-вариант структуры находится в `database/schema.sql`.

## Формы

Форма создания ресурса:

- страница `Админка -> Товары -> Добавить товар`;
- поля: название, категория, тип товара, цена, количество, изображение, описание, флаг рекомендации;
- используется HTML5-валидация, JavaScript-валидация и серверная проверка.

Форма поиска:

- страница `Каталог`;
- критерии: строка поиска, категория, тип товара, максимальная цена, наличие.

Дополнительные формы:

- регистрация;
- вход;
- восстановление пароля;
- оформление заказа;
- создание администратора;
- добавление категории;
- изменение статуса заказа.

## Безопасность

- Пароли не хранятся в открытом виде.
- Для авторизации используются PHP-сессии.
- Закрытые разделы проверяют наличие пользователя в сессии.
- Админ-панель дополнительно проверяет роль `admin`.
- Все данные форм проходят серверную валидацию.
- Вывод в HTML экранируется функцией `h()`.
- Изменяющие POST-запросы защищены CSRF-токенами.
- Токены восстановления пароля хранятся в виде SHA-256-хеша и имеют срок действия 1 час.

## Telegram-бот

В проект добавлен минимальный Telegram-бот `bot/bot.php`. Он использует тот же каталог товаров, что и сайт, и поддерживает команды:

```text
/start
/catalog
/product_1
/help
```

Для реального запуска нужен токен от BotFather:

```powershell
$env:BOT_TOKEN="123456:YOUR_TELEGRAM_BOT_TOKEN"
php bot/bot.php
```

Бот работает через long polling и не требует webhook, домена или дополнительных библиотек. Файл `data/bot_offset.txt` создается автоматически и хранит номер последнего обработанного сообщения.

## Ответы на контрольные вопросы

**Что такое аутентификация?**  
Это проверка личности пользователя по учетным данным, например email и паролю.

**Почему пароль нужно хешировать?**  
Хеширование защищает пароль: даже при доступе к базе злоумышленник не видит исходный пароль.

**Зачем нужна серверная валидация, если есть JavaScript?**  
JavaScript можно отключить или обойти, поэтому окончательная проверка всегда должна выполняться на сервере.

**Что такое сессия?**  
Сессия хранит состояние пользователя между HTTP-запросами, например идентификатор вошедшего пользователя.

**Что такое CRUD?**  
Это базовые операции с данными: Create, Read, Update, Delete.

**Зачем нужен CSRF-токен?**  
Он защищает формы от подделанных запросов, отправленных с другого сайта от имени пользователя.
