# DeviceStore

Учебное PHP-веб-приложение "DeviceStore" — это мини-магазин гарнитур, клавиатур, мышей и комплектующих с публичной витриной, регистрацией пользователей, оформлением заказов и админ-панелью. Проект дополнен минимальным Telegram-ботом, который использует тот же каталог товаров и работает без внешних библиотек.

## Запуск проекта

### Требования

- PHP 8.1 или выше
- Браузер
- Composer не требуется

### Установка и запуск

```bash
git clone https://github.com/hronikiz/devicestore.git
cd devicestore
php -S 127.0.0.1:8000 -t public
```

Откройте в браузере:

```text
http://127.0.0.1:8000
```

При первом запуске приложение автоматически создаст `data/store.json` и заполнит начальную базу.

### Учётные записи

```text
Администратор: admin@devicestore.local / Admin12345!
Покупатель:     user@devicestore.local / User12345!
```

### Сброс данных

Удалите файл `data/store.json`, затем перезапустите сервер.

## Описание лабораторной работы

Задача проекта — разработать серверное PHP-приложение магазина с публичной витриной, регистрацией, формами, защищённой логикой, админ-панелью и Telegram-ботом.

Основные требования:

- динамический каталог товаров;
- регистрация и авторизация пользователей;
- безопасное хранение пароля и восстановление доступа;
- оформление заказов;
- админ-панель с управлением товарами, категориями и заказами;
- защита форм и документирование проекта.

## Документация проекта

### Архитектура

Приложение реализовано без фреймворков. В проекте используется MVC-подход с разделением на:

- `src/App.php` — маршрутизация и контроллеры;
- `src/Core/` — аутентификация, CSRF, JSON-база, валидация;
- `src/Repositories/` — репозитории для доступа к данным;
- `src/Views/` — шаблоны страниц;
- `bot/` — Telegram-бот, использующий ту же базу данных.

### Структура проекта

```text
public/
  index.php              Точка входа сайта
  assets/                CSS, JS, локальные изображения
bot/
  bot.php                Скрипт Telegram-бота
src/
  App.php                Роутинг и логика приложения
  bootstrap.php          Конфигурация и автозагрузка
  helpers.php            Утилиты
  Core/
    Auth.php             Авторизация и сессии
    Csrf.php             Защита форм
    FileDatabase.php     Работа с JSON-базой
    Validator.php        Серверная валидация
  Repositories/
    CategoryRepository.php
    OrderRepository.php
    ProductRepository.php
    UserRepository.php
  Views/                 HTML-шаблоны
data/
  store.json             Автоматически создаётся
database/
  schema.sql             SQL-схема для отчёта
```

### Структура базы данных

В проекте используется JSON-файл `data/store.json` в качестве основной базы данных. Для отчёта представлена SQL-схема в `database/schema.sql`.

#### Таблицы JSON-базы

- `users` — пользователи, email, хеш пароля, роль, токены восстановления;
- `categories` — категории товаров;
- `products` — товары, цена, количество, описание, изображение;
- `orders` — заказы пользователей, адрес доставки, статус.

#### Реляционная схема

`database/schema.sql` описывает таблицы:

- `users(id, name, email, password_hash, role, reset_token_hash, reset_expires_at, created_at)`
- `categories(id, name, slug, created_at)`
- `products(id, category_id, name, product_type, price, stock, description, image_url, is_featured, created_at, updated_at)`
- `orders(id, user_id, product_id, quantity, unit_price, total_price, customer_telegram, customer_phone, delivery_address, note, status, created_at, updated_at)`

#### Связи данных

- `products.category_id` → `categories.id`
- `orders.user_id` → `users.id`
- `orders.product_id` → `products.id`

### Функциональные возможности

- Публичная главная страница с товарами и статистикой;
- Каталог с поиском и фильтрацией по названию, категории, типу, цене и наличию;
- Регистрация и вход пользователей;
- Восстановление пароля через токен;
- Оформление заказа в карточке товара;
- Личный кабинет с историей заказов;
- Админ-панель с CRUD для товаров, категорий, заказов и администраторов;
- CSRF-защита для всех POST-форм;
- Серверная и клиентская валидация данных;
- Единая база данных для сайта и Telegram-бота.

### Сценарии взаимодействия

#### Гость

1. Открывает главную страницу.
2. Просматривает товары и категории.
3. Использует поиск по каталогу.
4. Регистрируется или входит.

#### Авторизованный покупатель

1. Открывает карточку товара.
2. Заполняет форму заказа.
3. Оформляет заказ.
4. Просматривает заказ в `Мои заказы`.

#### Администратор

1. Заходит в админ-панель.
2. Просматривает статистику и новые заказы.
3. Управляет товарами и категориями.
4. Изменяет статусы заказов.
5. Создаёт администраторов.

#### Telegram-бот

1. Запускает бота командой `/start`.
2. Получает меню с каталогом и ссылкой на сайт.
3. Выбирает категорию.
4. Открывает товар кнопкой `#<id>`.

## Telegram-бот

Скрипт: `bot/bot.php`

- Использует общую JSON-базу `data/store.json`;
- Работает по long polling Telegram API;
- Поддерживает команды `/start`, `/catalog`, `/help`, `/support`, `/site`;
- Разбивает каталог на категории;
- Открывает товары по кнопкам `view_product_<id>`;
- Может отправлять локальные изображения из `public/assets/`.

### Запуск бота

```powershell
$env:BOT_TOKEN="123456:YOUR_TELEGRAM_BOT_TOKEN"
php bot/bot.php
```

### Настройки SSL

```powershell
$env:BOT_CACERT="C:\path	o\cacert.pem"
$env:BOT_TOKEN="123456:YOUR_TELEGRAM_BOT_TOKEN"
php bot/bot.php
```

Или для демонстрации:

```powershell
$env:BOT_ALLOW_INSECURE_SSL="1"
$env:BOT_TOKEN="123456:YOUR_TELEGRAM_BOT_TOKEN"
php bot/bot.php
```

## Ответы на контрольные вопросы

**Что такое аутентификация?**
Аутентификация — это подтверждение личности пользователя по учётным данным.

**Почему пароль нужно хешировать?**
Хеширование защищает пароль от раскрытия при утечке данных.

**Зачем нужна серверная валидация, если есть JavaScript?**
Потому что клиентскую проверку можно обойти, серверная валидация обязательна.

**Что такое сессия?**
Сессия хранит состояние пользователя между запросами.

**Что такое CRUD?**
CRUD — это Create, Read, Update, Delete, базовые операции с данными.

**Зачем нужен CSRF-токен?**
CSRF-токен предотвращает поддельные POST-запросы от других сайтов.

## Другие важные аспекты

- Проект не требует Composer и внешних библиотек.
- Все данные хранятся локально в `data/store.json`.
- Админ-панель проверяет роль `admin` и использует CSRF.
- Категории нельзя удалить, если в них есть товары.
- Telegram-бот работает с той же базой, что и сайт.
- В дальнейшем проект можно расширить реальной СУБД, загрузкой изображений, оплатой и вебхуками Telegram.
